## Findings

### 1. Persisted unclaimed results become unclaimable after a restart — REAL BUG (FIXED 2026-08-12)

`src/App.tsx:219-231` (`claimTab`)

`claimTab` early-returns unless `unseenStopsRef.current` — purely in-memory —
holds the tab id. After a relaunch that set is empty, so no `result_claimed`
event is ever written for a session whose `result_landed` row survived the
quit. Nothing else in the codebase writes `result_claimed`.

Effect: the Accomplished panel's "Agent finished, unclaimed" headline
(`SidePanel.tsx`, fed by `repo.unclaimedResults`, `src/lib/repo.ts:131`) pins a
stale row permanently. That is exactly the case persistence was added for — the
comment at `App.tsx:214-217` says the row exists so it "survives a restart",
and surviving is the one path where claiming is broken.

Reproduce: let an agent finish on a background tab, quit the app, relaunch,
switch to that project's tab with the window focused. The row stays.

Fixed by seeding `unseenStops` from the DB when ghost tabs are built at
startup. Every existing claim path then works unchanged — no new claim logic,
no schema change:

- `repo.unclaimedSessions()` (`src/lib/repo.ts`) — every session holding an
  unclaimed result, across all projects. Sibling of `unclaimedResults`, minus
  the cwd filter.
- `seedUnclaimedTabs(tabs, sessions)` (`src/lib/ingest.ts`) — pure, so the
  check script can assert it.
- `App.tsx` startup — seeds **before** `setActiveId`. This ordering is the
  subtle part: the `activeId` effect claims the tab it activates, so seeding
  after would leave the first restored tab flagged-but-active, stuck in the
  same way. All three `setState` calls batch into one commit, so the effect
  sees the seeded set.

Residual, deliberate: if a tab is re-entered *before* its old result is
claimed, the tab's `sessionId` advances to the resumed session and the claim
writes against that id, leaving the original `result_landed` row unclaimed.
Reaching it requires re-entering without the window ever taking focus.
Not worth a session-lineage column until it shows up in real use.

Covered by three new assertions in `scripts/unclaimed-check.ts`.

### 2. A `result_landed` row with no cwd is written but never readable — MINOR (FIXED 2026-08-12)

`src/App.tsx:346-350`

`sessionCwd.get(p.session_id)` can return `undefined`; `JSON.stringify({cwd:
undefined})` yields `"{}"`, and `unclaimedResults`' `json_extract(...,
'$.cwd') = $1` can never match that row. The event is persisted and then
invisible.

Narrow in practice — the Stop payload carries cwd, so the map is normally
populated by the time this runs — and it fails open rather than breaking
anything. Worth a guard only because a silently-unreadable row is harder to
debug later than a row that was never written.

Fixed: the persist is now guarded on `cwd` being present (`App.tsx`, the
`isStop` branch). The in-memory flag and the nudge still fire either way, so a
cwd-less Stop is no less visible than before — only the unreadable row is gone.

### 3. Ghost tabs lose their color and title — COSMETIC

`src/App.tsx:201-209`

Restored tabs hardcode `PALETTE[7]` and re-derive the title from the last path
segment of `project_key`. A user's renamed or color-coded tab comes back
generic. `session_bindings` (migration 7) stores no tab chrome, so this is a
schema gap, not a coding mistake.

Also note the knock-on: `PALETTE[7]` is the value `App.tsx:598` treats as "no
accent", so a restored tab's side panel header renders grey even if the project
has a bookmark color. Bookmark colors are already persisted, so the lazy fix is
to look up the color from bookmarks by cwd at ghost-build time rather than to
widen the schema.

## Non-issues — reviewed, no action

- **Startup with ghosts opens zero live tabs.** The user lands on an all-dead
  overlay. This matches PLAN.md's intent (re-entry is a deliberate act, not an
  automatic respawn), but it is the kind of thing that reads differently in the
  hand than on paper. Judge it during §16 and record the call.
- **`pty.rs:139-144` interpolates `{shell}` unquoted** into the `-c` string.
  Breaks only if `$SHELL` contains a space. Not a real macOS condition; not
  worth the quoting.
- **Mute cache (`mutedProjectsRef`) refreshes only via the panel's toggle
  callback.** Correct for a single-window app — nothing else can mutate the
  setting.
- **Dedupe key, epoch guard, tether, and self-ingestion defences** all match
  the invariants in CLAUDE.md. No drift found.

# Plan 022: Optional Safe Router model traffic view

> **Status: APPROVED FOR IMPLEMENTATION.** Drafted 2026-09-13 against accepted `main` at `2a4c481`. The maintainer explicitly authorized starting Plan 022 while Phase 33 testing is paused, bypassing that test gate. Implementation is isolated on `feat/safe-router-traffic` from `main`; no unaccepted Phase 33 work is imported. The agent-configuration and live tag-propagation experiment remain separately gated.

**Stated plan change during implementation:** The cached `rusqlite 0.40.2` requires `libsqlite3-sys 0.38.2`, which conflicts with `tauri-plugin-sql`/`sqlx-sqlite`'s `libsqlite3-sys 0.30.1`. The reader uses a direct `sqlx 0.8.6` dependency instead. Inspection of its installed `sqlx-sqlite` connection code confirms `.read_only(true)` sets `SQLITE_OPEN_READONLY` and it always sets `SQLITE_OPEN_URI`; the reader also uses a `file:...?mode=ro` URI and `PRAGMA query_only=1`. The security contract and separate connection boundary are unchanged.

**Additional file in scope:** `src/lib/modelTraffic.ts` holds the small, pure state/usage formatters tested by `scripts/model-traffic-check.ts`; this keeps formatting out of the component without adding SQL or persistence.

## 1. Outcome and boundary

Give the person running several agents a compact, global answer to the roadmap's *progress blindness* question: which routed requests are using which model tier, and with what reported usage, while work is in progress. Safe Router remains a separate process and sole log writer. The first release is a read-only recent-request list: time, client key **ID** (never key material), requested and served model, backend, plane, disposition and HTTP status, input/output token counters, and `usage_state`. Show at most the latest 100 rows by descending `id`, with a manual Refresh and a “latest 100” label. No cost, totals that treat missing usage as zero, tier-anomaly alert, rate-limit countdown, account switching, policy editing, router launch/configuration, new ingestion, or terminal input. The global view works even when no agent has proven tag propagation.

The external contract is `/Users/vandershark/Desktop/dev/safe_router/docs/LOG_CONTRACT.md`: `v_requests_v2` is available at schema `user_version` 2, keeps v1 fields and adds `usage_state`; the installed router's tagged request is reported to have produced a complete v2 row, but this plan does not rerun a model call. The contract makes `client_tag` client-controlled text, not proof of provenance. Its `tokens_in`/`tokens_out` are provider-reported best-effort counters, independently nullable; `complete` means both were recorded, `partial` one, `not_recorded` neither. Display each NULL as “unknown”/“—”; retain a real integer 0 as 0. Explain that `usage_state` describes the log, not provider billing completeness. No pricing source or incomplete-data policy is approved, so show no money.

## 2. Current-code decision record

- `src/lib/repo.ts` owns typed database calls and currently opens only `sqlite:context-terminal.db` through `@tauri-apps/plugin-sql`. `src-tauri/src/lib.rs` registers that plugin with migrations and a broad `sql:allow-execute` capability in `src-tauri/capabilities/default.json`. An `ATTACH` to this writable connection cannot meet Safe Router's connection-level read-only contract; do not use it or route the external file through the existing writable plugin pool.
- Add a dedicated Rust `safe_router_traffic` command/module that opens exactly `~/.safe-router/log.db` with SQLite `SQLITE_OPEN_READ_ONLY | SQLITE_OPEN_URI`, using `file:...?...mode=ro`, then sets `PRAGMA query_only=1` on that same connection. The direct `sqlx-sqlite` connection supplies these flags as noted above. Check file existence without creating it, read `PRAGMA user_version`, verify `v_requests_v2` exists in schema metadata, then select an explicit field list **only from `v_requests_v2`**. Metadata/pragma checks are allowed; never select, insert, update, migrate, or inspect data in `requests`. Do not silently fall back to v1: it lacks `usage_state`, a first-release field. Treat v1 as a distinct unsupported state.
- The command takes no caller-supplied path, SQL, or arbitrary limit. The fixed query selects `id, ts, plane, key_id, model_req, model_served, backend, disposition, status, tokens_in, tokens_out, usage_state, client_tag FROM v_requests_v2 ORDER BY id DESC LIMIT 100`. Map rows to a bounded typed result; validate required fields and known `usage_state` values. Use a short busy timeout and SQLx's async SQLite worker so a locked/unreadable file cannot occupy the webview/main thread. Open per refresh and drop the connection after the bounded read; there is no shared state with the app database or ingest server.
- Expose the command only through a typed `readSafeRouterTraffic(): Promise<TrafficSnapshot>` wrapper in `src/lib/repo.ts`; components call it and contain no SQL. `TrafficSnapshot` is a discriminated state (`missing`, `v1`, `ready` with rows, `error` with bounded safe copy). The Rust command catches open/schema/query failures into these states rather than propagating a fatal app error. Never surface raw filesystem paths, SQL text, or arbitrary SQLite error strings in the UI.
- `src/App.tsx` owns global overlays such as `AttentionInbox`; `src/components/AgentStatusBar.tsx` has the work controls and Setup button. Add a quiet “Traffic” control there and a compact overlay (patterned on `AttentionInbox`) rather than a section in `SidePanel`'s project-specific expanded/compact rail. The router log has no project key, and no agent is yet proven to send `X-Safe-Router-Tag`; a project rail would imply unsupported attribution. The control is always low-emphasis and reveals “Safe Router log not found” on opening when absent; no empty-count badge or warning strip on the ordinary workspace. The view remains useful as a global model/disposition audit without a project join.

## 3. UI states, attribution, and refresh

1. Render `missing` as “Safe Router log not found on this Mac”; `v1` as “Older Safe Router log; this view requires v2”; `ready` with `rows.length === 0` as “Log opened; no routed requests recorded”; `error` as “Traffic unavailable — could not read the router log,” with Retry. A loading state never masquerades as empty. A later refresh failure may keep last-good rows only if clearly labeled stale with the last successful refresh time. A v2 file with a missing/broken v2 view is a contract error, not an empty log.
2. Use ordinary React text nodes for every router-supplied string, especially `client_tag`; no `dangerouslySetInnerHTML`, HTML/Markdown interpretation, `innerHTML`, URL construction, or raw diagnostic interpolation. Bound visible text length in the row and reveal long values only as escaped text. Show the tag as an opaque label, not a trusted session name. No row gets a project label: the external view has no project key. If later tag attribution is approved, match exact full tags only to known current tab IDs after a live agent-specific header-propagation proof; absent/unmatched/sentinel tags remain “Unattributed.” A match is a navigation hint, not authority over the tab or proof of past project identity. Do not infer from cwd, key ID, model, or `LOGIC_LOOP_TAB_ID` alone.
3. Fetch on overlay open and manual Refresh; while open, poll no faster than every 15 seconds, with one request in flight, no queue of missed ticks, and a stale-response generation/cancelled guard. Tear down the interval on close/unmount and across React StrictMode double-mount; no new Tauri event listener is needed. Never poll while the overlay is closed. A short Rust busy timeout, bounded query, and error-as-state behavior keep failures off the terminal/ingest paths. A changing log is read through SQLite WAL's normal reader behavior; no router coordination or file watcher.

## 4. Client-tag experiment, separately gated

The smallest useful proof is **one** user-authorized agent-specific request, starting with one installed Codex session in a Logic Loop tab. First verify the installed Codex version offers a documented, session-local way to set a fixed `X-Safe-Router-Tag` header for its Safe Router endpoint; do not assume a PTY environment variable or Logic Loop's `X-Logic-Loop-Tab` hook header reaches model HTTP traffic. If no session-local header mechanism is supported, record “unproven” and stop the experiment. With separate authorization for any client setup and any `~`/global configuration change, route just that disposable session through the existing router, send one minimal human-triggered request, and compare the new `v_requests_v2.client_tag` byte-for-byte to that tab's ID; use an existing untagged row or local fixture as the unattributed control, without a second model request. A direct `curl` with the header only proves the router records tags (already reported), not that Codex propagates them. Do not make this experiment a launch blocker or turn on attribution for Claude, OpenCode, or Antigravity by analogy. Any implementation to inject headers into agent launches is a separate plan and authorization, not this panel.

## 6. Verification and failure cases

Assert the production query names only `v_requests_v2`, has an explicit column list and fixed LIMIT, and leaves the external file's contents unchanged. A fixture with an actively writing WAL connection must allow a concurrent bounded reader. Focused TypeScript checks cover distinct copy for all states, escaped hostile tag rendering (React text, no HTML interpretation), absent/unmatched tags, real zero vs unknown, stale-result suppression, and timer cleanup.
